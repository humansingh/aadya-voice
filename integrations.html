Integration patterns

Put Aadya where people already ask for help.

Add voice-first guidance to an existing portal, assisted-service desk or mobile journey without asking people to learn a new system first.

A practical map, not an SDK claim

These are prototype patterns. Public APIs, tenant authentication, quotas and partner write-back still need a production backend before third-party rollout.

Prototype onlyNeeds adapterNot supported

Three useful ways to integrate.

Each pattern keeps the conversation short, returns a sourced answer and preserves the host product as the place where the person completes the task.

01 · WEB

A voice help panel inside a public portal

Open Aadya beside a complex scheme page so a person can ask what the page means and leave with documents and the official next step.

Pattern · iframe or Web Component shell + signed session context
02 · ASSISTED SERVICE

A repeatable answer desk for frontline staff

Give CSC, ASHA and NGO teams one language-aware console that produces the same source, checklist and referral for every person.

Pattern · deep link with language/persona + case-note export
CONTINUE IN APP
03 · MOBILE

A guided handoff inside an existing mobile app

Let a banking, health or education app launch the right Aadya task, then return the person to the host app to apply, book or upload.

Pattern · universal link now; authenticated native wrapper later

What connects—and what deliberately does not.

Aadya explains and prepares. The system that owns the transaction should continue to decide eligibility, accept documents and move money.
